Call-Me Planner

A personal planner for one person with three areas of work. It saves tasks for today and tomorrow, groups them by company and plan, and refuses to let you forget. If a must-do task is still open after its time, the app rings like an incoming call and plays a voice note you recorded for yourself.

Personal Company A Company B Single user Phone app + browser app Works offline
The signature feature

The escalation ladder

Every task marked Must do gets a reminder ladder. Each step is louder than the last, and the ladder stops the moment the task is done, snoozed or moved on any device. Normal tasks get only the first two steps, so you don't get alarm fatigue.

  1. T − 15 min Heads-up Quiet notification: "Send invoice in 15 min". Phone, offline
  2. T 0 Voice alert Notification with your recording attached. Tap to hear it. Phone, offline
  3. T + 10 min Ring screen Full-screen "incoming call" with a looping ringtone. Answer and your recording plays. Phone, offline
  4. T + 20 min Real phone call The server calls your actual number and plays your recording. Press 1 = done, 2 = snooze, 3 = tomorrow. Server, Twilio
  5. T + 40 min Buddy nudge Optional. One SMS to a friend you chose: "Your friend hasn't finished a must-do task yet." Server, opt-in

The timings are defaults. Each workspace has its own policy (Company A can ring sooner than Personal), and any task can override it. Phone calls and buddy texts never happen during quiet hours unless the task is marked critical.

What "answering" does

  • Picking up stops the ringtone, opens the app's call screen and plays your recording on the speaker.
  • Three big buttons: Done, Snooze, Move to tomorrow. Ignoring the call counts as a missed ring, and the ladder moves on.
  • Snooze limit: after 3 snoozes the button disappears, so the task has to be done, moved or dropped.
  • Recordings are capped at 60 seconds, compressed AAC mono (about 15 KB per 10 s), stored on the phone and in a private cloud bucket so the phone-call step can play them.
  • If you didn't record anything, a text-to-speech voice reads the task title instead.
Platform decision

Why this must be a native phone app

A web app (PWA) can't ring like a call. The browser can't wake up at an exact time, can't show a full-screen alert and can't break through silent mode. The ring screen needs native phone APIs, so the main client is a React Native app built with Expo. The same codebase also builds a browser app with full control: tasks, plans, reminder rules, settings and voice notes. Every change made there reaches the phone, which re-plans its alarms. The browser itself never rings.

Reminder engine

Life of a reminder

stateDiagram-v2
  [*] --> Scheduled
  Scheduled --> HeadsUp: T-15
  HeadsUp --> VoiceAlert: T 0
  VoiceAlert --> Ringing: T+10 still open
  Ringing --> Answered: picked up
  Ringing --> PhoneCall: T+20 missed
  PhoneCall --> Answered: picked up
  PhoneCall --> PhoneCall: no answer, retry once after 5 min
  PhoneCall --> BuddyNudge: still no answer
  Answered --> Done: Done
  Answered --> Snoozed: Snooze
  Answered --> Moved: Tomorrow
  Snoozed --> Ringing: snooze ends
  BuddyNudge --> Exhausted
  Done --> [*]
  Moved --> [*]
  Exhausted --> [*]

From any state, finishing the task on any device jumps straight to Cancelled. Every transition is written to reminder_event, so the Review screen can show "you needed a phone call 4 times this week".

Who runs which step

  • The phone schedules heads-up, voice alert and ring with the operating system as soon as the task is saved. They fire with no internet and with the app closed.
  • The server only runs phone calls and buddy SMS, from a worker that checks every minute.
  • Only one device is the alarm device (a setting), so two phones never ring for the same task.

How a phone call is made

  • The worker finds reminder rows with channel = phone_call, due now, task still open, not in quiet hours.
  • It asks Twilio to call your verified number. Twilio fetches instructions from a webhook: say the task, play your recording from a 10-minute signed link, then wait for a keypress.
  • The keypress webhook marks the task done, snoozed or moved, and sends a silent push so the phone cancels its own alarms.

Each feature removes one excuse: "I forgot to write it down", "I forgot it existed", "I forgot to look", or "I didn't feel like it".

Sync

Offline first, synced when online

  • The phone's SQLite database is the source of truth for the screens. Screens never wait for the network.
  • Ids are UUIDs made on the device, so tasks can be created offline.
  • Every write also goes into an outbox. When NetInfo says you're online, the sync engine pushes it with supabase.from(table).upsert(...). A trigger on each table keeps the newest edit by updated_at and stamps server_updated_at = now().
  • Pull asks each table for .select().gt('server_updated_at', since), starting a few seconds early so no row is missed. A Realtime ping tells other devices to pull right away.
  • Deletes are soft (deleted_at) so they sync like any other change. A nightly job purges rows deleted more than 30 days ago.
  • Changes made in the browser (new task, new time, done, new reminder rules) reach the phone by silent push, because a sleeping phone may not be listening to Realtime. The phone pulls, re-plans and re-schedules its alarms, then reports "alarms armed" back to the browser.

Security and privacy

Guard rails

Your data

  • Row-level security on every table, so one account can never read another's rows.
  • Recordings are private. Twilio gets a signed link that expires in 10 minutes.
  • One-tap JSON export of everything, plus a weekly automatic export to your own Google Drive.
  • Company tasks stay generic. Don't paste client data, passwords or code. Check your contracts.

Calls and money

  • Your phone number and your buddy's are verified with a one-time code before the app can ever call or text them.
  • Every Twilio webhook checks Twilio's request signature, so nobody else can trigger "mark done".
  • Hard cap of 10 calls and 5 SMS per day to control cost.
  • API keys live only in Edge Function secrets, never in the app.

Risks

What can go wrong

Phone makers kill alarms

Some Android phones (Xiaomi, Oppo, Samsung) stop background apps to save battery. Onboarding walks you through "allow alarms" and "don't optimise battery", and the app uses the alarm-clock API, which is the hardest one for the system to delay.

Store rules

Google Play requires a declaration for exact alarms and full-screen alerts (allowed for alarm apps). Apple rejects fake call screens, which is why iOS uses AlarmKit plus a real Twilio call.

Call cost and numbers

Twilio charges per minute plus a monthly fee for the number. Prices change, so check them before Phase 2. Some countries, including Australia, need ID or address checks to buy a local number. The daily cap limits surprises.

Alarm fatigue

If everything rings, you'll start ignoring it. Only must-do tasks escalate, snoozes are limited, and Review shows which workspace needs calls most so you can fix the plan, not just the alarm.

Open decisions: whether a company pays by the hour (moves the time tracker earlier), which phone you use (Android gets the full ring screen in Phase 1, iPhone needs iOS 26 or later for it), and whether you want the buddy feature at all.
